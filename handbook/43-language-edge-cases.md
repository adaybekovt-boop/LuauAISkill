# 43. Luau: края языка, которые ломают надёжные системы

Авторский синтез; проверка первичных источников 26.09.2026. Не официальный перевод и не отчёт о выполненном Studio-тесте.

## Значения и форма данных
В обычной Luau number-семантике нельзя считать произвольный большой десятичный ID точным числом. Учитывать диапазон точного целого выбранного representation; opaque identifiers безопаснее сохранять в документированном формате. При сериализации проверить, что число конечное и не стало NaN/Inf после промежуточного вычисления.

Таблица может одновременно содержать последовательную и словарную части. `#t` не является надёжным числом элементов произвольного sparse dictionary. Для массивов сохранять плотность или явный count. Не полагаться на случайный порядок словарных ключей при deterministic hashing, сериализации или симуляции: собрать и отсортировать канонический набор ключей.

## Множественные значения
Возврат функции и `...` — набор значений, а не автоматически один массив. При упаковке nil нужен table.pack с `n`, иначе length/распаковка потеряют trailing nil. В публичном API лучше не менять незаметно `(value, error)` на одну таблицу: потребители будут получать иной контракт. Tagged Result полезен, когда нужно отличать корректное false от ошибки.

Замыкания удерживают ссылку на state, пока доступны; module singleton удобен, но повторное require в другом host не создаёт общую сетевую память. Тест, который случайно использует кеш модуля от предыдущего случая, может скрыть init-дефект. Для изоляции хранить mutable state в new(), а не безусловно на уровне файла.

## Metatables и мутация
Метаметоды — не бесплатная магия и не универсальное OOP. Не выполнять непредсказуемую внешнюю работу при обычном чтении свойства. Глубокий __index chain затрудняет типизацию и профилирование. table.clone и table.freeze не означают глубокое копирование/заморозку вложенных объектов; alias ownership описать явно.

Не переносить `goto`, произвольное чтение файлов, C extensions, package/loadfile или синтаксис последних Lua-версий в Roblox по аналогии. Sandbox/host API и спецификация языка различаются. Строковый require для standalone CLI и ModuleScript require для Studio — разные installation recipes, даже если модульный код одинаковый.
