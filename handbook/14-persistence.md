# 14. Сохранения: состояние, конкуренция и отказ

Срез проверки: **26 сентября 2026**. Это авторская рабочая методика, не полный перевод официальной страницы. Непроверенные в Studio рецепты требуют отдельного запуска.


## Не учить агента терять данные
Загрузка имеет состояния Loading, Ready, ReadOnly/Error и Closing. Ошибка GetAsync не равна отсутствию профиля. Нельзя после сбоя подставить defaults, позволить обычную игру и затем сохранить defaults поверх существующего прогресса. Запретить опасные изменения или перейти в явно ограниченный режим с уведомлением.

UpdateAsync получает текущее значение; transform должен быть без yield и внешних side effects. Он может быть выполнен повторно. Нельзя внутри него выдавать предмет в Workspace, списывать внешнюю валюту, ждать HTTP или считать, что каждый вызов соответствует единственному commit. Сохранение нескольких связанных значений в одной записи облегчает атомарность, но не даёт транзакцию между разными ключами.

## Авторская архитектурная спецификация
Один owner профиля, последовательная очередь операций по ключу, schemaVersion, migration chain, dirty flag и bounded autosave. При session locking нужны атомарный захват, срок/heartbeat, fencing identity и проверка права на каждый commit. Простая Bool-переменная на сервере не защищает от второго сервера. Истечение lock не даёт старому владельцу права продолжать запись.

Повторять только допустимые ошибки с backoff/jitter и лимитом попыток. Retry старого snapshot после нового commit способен откатить прогресс. Поэтому порядок и версии важнее наличия pcall. Сохранять metadata/UserIds там, где они использованы. Для shutdown есть отдельный ограниченный сценарий; не обещать, что аварийное завершение всегда дождётся сохранения.

## Тестовая матрица
Отказ загрузки; отказ первого/последнего save; повтор transform; два сервера; stale lock; reconnect до завершения предыдущего save; миграция неизвестной версии; повреждённая запись; лимит хранилища. Не запускать destructive тесты на production stores. Пакет намеренно не выдаёт игрушечный DataStore-скрипт за production-ready библиотеку профилей.
