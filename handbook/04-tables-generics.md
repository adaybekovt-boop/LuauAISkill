# 04. Таблицы, generics и проектирование данных

Срез проверки: **26 сентября 2026**. Это авторская рабочая методика, не полный перевод официальной страницы. Непроверенные в Studio рецепты требуют отдельного запуска.


## Таблица — не универсальное оправдание хаоса
Определить ключи, владельца мутаций, формат сериализации и правила копирования. Отделять массив с последовательными индексами от словаря. Не удалять элементы массива по возрастанию индексов, одновременно полагаясь на неизменность следующих индексов. Для разреженных данных не использовать # как надёжный подсчёт элементов.

Статически sealed table не становится неизменяемой в runtime. table.freeze и локальная const-привязка тоже решают разные задачи: freeze не означает автоматическую глубокую заморозку вложенных объектов, а неизменяемая переменная не делает её содержимое immutable. Для публичной конфигурации решить, достаточно ли shallow freeze, или создавать новые вложенные таблицы на границах.

## Когда generic полезен
Result<T>, bounded queue<T>, cache<Key,Value> сохраняют отношения типов без any. Но не нужно превращать трёхполевую конфигурацию двери в библиотеку type functions. Типовая метапрограмма должна уменьшать ошибки, а не делать сообщения анализатора нечитаемыми. Type functions выполняются на этапе анализа, не заменяют runtime-валидацию сетевого сообщения.

## Метатаблицы и композиция
Модуль с new/start/destroy может быть удобен. Важно, чтобы destroy был идемпотентен, start не создавал двойные подписки, а конструктор не запускал вечные процессы до завершения проверки аргументов. Владение соединениями/таймерами должно быть видно в коде. Скрытая глобальная registry под видом OOP создаёт те же утечки, что и обычный глобальный словарь.

Задать тесты: два экземпляра не делят mutable default table; повторное уничтожение безопасно; экспортированные типы совпадают с реальными результатами; сериализация не содержит функций, userdata или Instance; миграция старой схемы не мутирует чужую запись неожиданно. Когда порядок элементов влияет на детерминизм, документировать сортировку, а не надеяться на одинаковый hash traversal.
