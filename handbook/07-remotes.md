# 07. Сетевые контракты и RemoteEvent

Срез проверки: **26 сентября 2026**. Это авторская рабочая методика, не полный перевод официальной страницы. Непроверенные в Studio рецепты требуют отдельного запуска.


## Сначала протокол
Для каждого remote описать отправителя, получателя, схему, частоту, максимальный размер, права, ответ, timeout и правила повторов. Названия вроде DoEverything(payload) затрудняют аудит. Предпочтительнее RequestInteract(targetId, sequence) с маленьким контрактом и серверным разрешением targetId.

RemoteEvent односторонний и не возвращает результат синхронно. RemoteFunction блокирует вызывающий поток до результата; серверный критический путь не должен зависеть от надёжности ответа клиента. Для request/response поверх событий задать requestId, ограниченный словарь pending, timeout и cleanup. Не делать unbounded retry.

UnreliableRemoteEvent подходит для данных, которые можно потерять и заменить следующим обновлением: визуальный aim pose или краткоживущий эффект. Покупка, выдача предмета, итог матча и сохранение требуют другого контракта. Не считать сетевую доставку гарантией того, что объект, переданный в сообщении, уже существует на принимающей стороне.

## Сервер решает
Первый Player в OnServerEvent сообщает движок. Отдельный playerId из payload не является доказательством личности. Клиент передаёт намерение, сервер проверяет существование цели, дистанцию, состояние и стоимость. Возвращать только данные, нужные этому клиенту, а не весь серверный профиль.

Дорогая проверка после rate limit защищает меньше, если до лимитера уже выполнен перебор тысячи частей. Ограничитель имеет лимит на игрока и действие, cleanup на PlayerRemoving и метрику отказов. Не создавать новую запись по каждому произвольному actionName из payload: это само по себе путь к росту памяти.

Приёмка: два клиента одновременно активируют один объект; один клиент отправляет stale sequence; сообщение приходит после respawn; цель выгрузилась; отсутствует ответ; payload не проходит схему. Для каждого случая поведение заранее определено.
