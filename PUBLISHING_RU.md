# Публикация в adaybekovt-boop/LuauAISkill

## Фактический статус этой поставки
Репозиторий проверен через подключение GitHub: он доступен и был пустым. **Из чата ничего не закоммичено и не отправлено.** Доступные в этой сессии команды GitHub — чтение; команды записи/авторизованного git push нет. Не путайте готовый к публикации ZIP с опубликованным репозиторием.

## Публикация ядра с компьютера
Распакуй ZIP. Нужны Python 3.10+ и установленный Git. Запусти `PUBLISH_TO_GITHUB.cmd` в корне распакованной папки. На macOS/Linux: `sh publish_to_github.sh`.

Скрипт использует уже настроенный Git Credential Manager или авторизованный GitHub CLI. При отсутствующей авторизации Git может предложить войти в аккаунт через браузер. Не вставляй пароли/токены в чат. Ошибку доступа скрипт не обходит и не выдаёт за успешную публикацию. Учетная запись должна иметь право записи, включая workflows: политика конкретного способа авторизации может потребовать отдельного разрешения на `.github/workflows/`.

Без сети проверить будущий набор можно так:
```sh
python tools/publish_github.py --dry-run
```

Публикуются **только** файлы из проверенного `PACK-MANIFEST.json`, а не содержимое соседних папок. Скрипт клонирует целевой репозиторий во временную папку, копирует пакет, делает коммит и проверяет, что SHA удалённой ветки совпадает с локальным. `--force` не используется; чужие файлы не удаляются. Пустой репозиторий получает `main`; существующий — отдельную ветку. Если существующий файл отличается, публикация останавливается для ручного ревью. Это импорт, не инструмент произвольного обновления репозитория.

## Получение полного корпуса на GitHub
После публикации ядра открой **Actions → Build full official corpus → Run workflow**. По умолчанию используются commits из `sources/pins.json`; `latest` — отдельный осознанный выбор. Workflow только читает публичные источники и создаёт скачиваемый artifact `LuauAISkill-full-corpus`. Он **не коммитит** тысячи документов обратно в main и не публикует Release автоматически.

Успех — зелёный результат workflow, `upstream/DOWNLOAD-REPORT.json` с полной загрузкой обоих источников, проверенные хеши и приложенный ZIP. При сбое прикладывается диагностика, а не архив, названный полным. Стоимость и доступность GitHub Actions зависят от настроек аккаунта; эта сборка не меняет биллинг.

## Получение полного корпуса локально
Запусти `DOWNLOAD_FULL.cmd` или `sh download_full.sh`. После успешной загрузки пересоздаются поиск, отчёты, манифест и расширенный ZIP. Загрузчик не исполняет код из документации. Видео, изображения, ассеты и компилятор не скачиваются.

Для публикации уже расширенной папки сначала убедись, что сборка завершилась успешно. Затем тот же `PUBLISH_TO_GITHUB.cmd` может импортировать эту папку в ещё пустой репозиторий; если там уже есть отличающаяся версия ядра, он корректно откажет вместо перезаписи.

## Обновления
Обычные изменения проекта делай через стандартный Git workflow и ревью. Не регенерируй манифест, чтобы спрятать неизвестное изменение: сперва выясни его причину. После проверенных правок запусти `python tools/release_pack.py`. Первичный отчёт QA не является доказательством тестирования будущих версий.
