# 44. Buffers и компактные данные без хрупкого протокола

Авторский синтез; проверка первичных источников 26.09.2026. Не официальный перевод и не отчёт о выполненном Studio-тесте.

## Сначала схема, потом экономия байтов
Buffer полезен для компактных бинарных данных, но не делает вход доверенным. Протокол должен иметь version, длины, units, диапазоны, endian/encoding и правила для неизвестных полей. До любого чтения проверить минимальный размер и смещение. Во вложенных структурах ограничить count и суммарную стоимость декодирования.

Нельзя брать remote-пayload из интернета и читать offset 20 только потому, что «клиент всегда присылает 24 байта». Модель угроз включает пустой/обрезанный/oversized buffer, неверную версию, огромные count, повтор sequence и значения вне разрешённой области. Типы Luau не описывают автоматически содержимое байтов.

## Quantization
Сжатие позиции задаёт диапазон мира и шаг точности; угол и скорость имеют собственные погрешности. Сначала определить максимально допустимую error budget в игровой механике. Если ошибка может изменить попадание, collision или ranking, косметический протокол нельзя использовать как единственный authoritative state.

Для каждого поля документировать encode/decode, крайние допустимые значения и поведение overflow. Saturation, отказ и wrap — три разных поведения. Не позволять переполнению вернуть координату на противоположный конец карты. Вычислять error на representable пределах, а не только на случайных средних значениях.

## Производительность и тесты
Сравнивать полную стоимость encode + transfer + decode + allocations с обычной таблицей на репрезентативных пакетах. Маленький payload не всегда оправдывает сложность и риск ошибки. Записывать размеры и частоту, а не объявлять «buffer всегда быстрее в пять раз».

Round-trip property tests должны включать zero, limits, negative, truncation, huge count, unsupported version, malicious text lengths и repeated packets. Отдельно test identity/policy validation после decode. Сетевое сжатие — механизм представления, не permission system и не защита от изменённого клиента.
