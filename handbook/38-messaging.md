# 38. Cross-server messaging и консистентность

Авторский синтез; проверка первичных источников 26.09.2026. Не официальный перевод и не отчёт о выполненном Studio-тесте.

## Событие не является транзакцией
MessagingService связывает серверы через topics. Сообщение «обновлён рейтинг» полезно как сигнал перечитать данные, но не заменяет durable запись. Для финансовых/инвентарных операций сначала продумать атомарность в источнике истины и только затем публикацию уведомления.

Схема сообщения включает protocolVersion, eventId, sender/session identity где нужна, тип события и небольшой payload. Topic не должен содержать секреты. Сообщение из связанной инфраструктуры всё равно проходит shape/range/semantics validation. Нельзя позволить публичному remote задавать произвольное содержимое административного объявления.

## Реакция на повтор и пропуск
Без документированной exactly-once гарантии проект не должен на ней строиться. Consumer должен выдерживать повтор по eventId, неизвестную версию и позднее событие. Дедуп-кэш ограничен размером и временем, иначе «защита от повторов» сама превращается в memory leak. Для текущего состояния полезен version/revision, чтобы старое событие не откатило новое.

Если всем клиентам текущего сервера нужно одно объявление, обычно достаточно одного server-level subscription и локального fan-out, а не подписки на тот же topic для каждого игрока. Это инженерное решение зависит от задачи; tutorial с per-player subscription не является универсальным production pattern.

## Жизненный цикл
SubscribeAsync/PublishAsync могут завершаться ошибкой. Реестр подписок принадлежит одному service и освобождается при остановке. Retry ограничен; ошибочные payload не пересылаются бесконечно. Server browser показывает lastSeen и считает просроченный сервер недоступным, вместо обещания, что любая запись всё ещё активна.

Проверять повтор, неизвестный eventType, недоступность сервиса, restart двух серверов, отсутствие подписчика во время публикации, stale listing и локальный remote flood. В отчёте различать реальные cross-server проверки в опубликованном client от unit-теста сериализатора.
