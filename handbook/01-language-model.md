# 01. Luau, Lua и Roblox — разные уровни

Срез проверки: **26 сентября 2026**. Это авторская рабочая методика, не полный перевод официальной страницы. Непроверенные в Studio рецепты требуют отдельного запуска.


Luau — язык, а Roblox Engine — среда исполнения с игровыми объектами. Из документации стандартной библиотеки нельзя вывести существование DataStoreService, task или Instance в самостоятельном CLI. Из примера Lua 5.4 нельзя механически переносить библиотеку io, файловую систему, сборку модулей, загрузку C-модулей или особенности операторов в Roblox.

## Проверка границы среды
В README каждого модуля написать: pure Luau, Roblox shared, server-only, client-only или Studio-only. Pure-модуль не должен скрыто читать workspace, game, script или локальные файлы. Он получает состояние и зависимости аргументами. Так можно тестировать доменную логику отдельно, не подменяя полноценную игру заглушками.

## Значения и ошибки
Таблица передаётся по ссылке внутри одного VM: изменение вложенной таблицы затронет другие ссылки. Пустая таблица и 0 являются truthy; false и nil — нет. Не использовать `value or default`, когда false — допустимое значение. Для необязательного bool сравнивать с nil явно. Числа не обеспечивают бесконечной точности: для счётчиков/валюты задать целые безопасные пределы и запрет нечисловых/неfinite входов.

`pcall` ограничивает распространение исключения, но не откатывает уже сделанные изменения. Если функция списала предмет, затем упала при выдаче награды, pcall не восстановит инвентарь. Разделять валидацию, подготовку, commit и presentation. Для ожидаемых отказов применять tagged Result; аварийные ошибки логировать с контекстом и без секретов.

## Как учить модель
Дать одну задачу сначала с чистой логикой, затем с адаптером Roblox. Например, cooldown считает только число времени; RemoteEvent-обработчик получает Player и проверяет запрос; UI только отображает результат. Такая декомпозиция обнаруживает ошибки лучше, чем универсальный модуль на 1500 строк.

Проверки: false не теряется при defaulting; nil отличается от пустой строки; исходная таблица не мутируется неожиданно; каждый отказ имеет определённое состояние после операции; внутри shared-модуля нет серверных секретов.
