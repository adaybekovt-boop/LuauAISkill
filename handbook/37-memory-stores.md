# 37. MemoryStore: временная координация, а не вечный сейв

Авторский синтез; проверка первичных источников 26.09.2026. Не официальный перевод и не отчёт о выполненном Studio-тесте.

## Подходящая задача
MemoryStore служит для часто меняющихся временных данных между серверами: очереди матчей, краткоживущие объявления, координационные записи и кэш. Durable прогресс остаётся в DataStore. TTL — часть модели, а не неприятное исключение. После истечения или потери cache система должна уметь восстановиться из источника истины.

Hash map подходит для lookup по ключу, sorted map — для упорядоченных данных, queue — для обработки элементов. Не выбирать одну giant sorted map на всю игру просто потому, что она напоминает словарь. Бюджеты бывают уровня game, partition и горячего key; успешный локальный тест не проверяет общую межсерверную нагрузку.

## Очередь и повтор
Обработка может начаться, а воркер упасть до удаления элемента. Поэтому проектировать idempotent consumer с operation ID и допустимым повтором. «Прочитано из очереди» не равно «durable результат записан». Удаление до выполнения теряет работу, удаление после выполнения допускает повтор: нужен явный протокол, а не надежда на идеальный порядок.

Временный reservation матча содержит owner/session ID, participants и expiry. Если участник вышел, сервер упал или teleport не состоялся, reservation должен освободиться без бесконечного ожидания. Продление TTL без проверки владельца может удерживать чужую работу.

## Нагрузка
Для каждого operation определить размер payload, запросы в секунду, fan-out, хранение до удаления и backoff. Численные quotas не зашивать навечно из этой методички: перед релизом читать актуальный лимит и dashboard. Исчерпание бюджета должно ухудшать необязательную функцию, а не отправлять все серверы в retry storm.

## Тестовый план
Симулировать expiry, повторное сообщение, падение воркера между выполнением и подтверждением, hot key, пустой ответ и throttling. Официальная страница описывает изоляцию Studio MemoryStore от production; этот факт не переносится автоматически на DataStore. Даже при изоляции нужна отдельная среда и понимание, какие реальные сервисы вызываются.
