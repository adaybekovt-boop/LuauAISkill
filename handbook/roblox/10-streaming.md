# Instance streaming and large worlds

Read when: big maps, open worlds, mobile memory problems, client scripts that break because objects are missing,
LOD. Related: [lifecycle binder](02-lifecycle-events.md#tagged-objects-collectionservice-binder-replaces-scripts-inside-every-model),
[terrain](11-terrain.md), [procedural](12-procedural-generation.md), [performance](08-performance.md).

## The contract a client script must honour
With `Workspace.StreamingEnabled` (on by default for new places; **Studio-only setting**, not scriptable), a client
has only part of `Workspace`. Any Workspace `BasePart` (and non-persistent models) may be **absent**, may arrive
later, and may **disappear** (stream out → parented to `nil`, not destroyed) and come back as the same Instance.
Server scripts always see everything. Streaming applies only to `Workspace` descendants — ReplicatedStorage and
ReplicatedFirst are fully replicated.

Therefore on the client:
- Never assume `workspace.Map.Door` exists at startup. Use tags + a binder (bind on added, clean up on removed),
  `ChildAdded`, or `WaitForChild(name, timeout)` with a nil path.
- A remote that references a Workspace Instance may deliver `nil` if it isn't streamed in.
- Raycasts/overlaps on the client miss non-streamed parts; SLIM/terrain imposters are visual only.
- Client-created instances are exempt from stream-out unless parented under a server-created instance.
- Client physics simulation happens only inside streamed areas.
- A `Model` with no BaseParts (script container) replicates at join and is exempt from stream-out.

## Settings (all on `Workspace`, Studio-only)
| Property | Meaning | Guidance |
|---|---|---|
| `StreamingMinRadius` (default 64) | always-kept radius, highest priority | raise carefully (memory + server bandwidth) |
| `StreamingTargetRadius` | max stream-in distance | must be > min radius (buffer); lower for mobile-heavy games |
| `StreamOutBehavior` | `LowMemory` (default: stream out only under memory pressure) / `Opportunistic` (stream out beyond target radius proactively) | Opportunistic for huge worlds |
| `StreamingIntegrityMode` | what to do if the player enters an unloaded region | `PauseOutsideLoadedArea` recommended; `Player.GameplayPaused` indicates pause |
| `ModelStreamingBehavior` | `Legacy` (default) / `Improved` (models stream with their parts) | Improved for new projects |
| `PredictiveStreamingMode` | opt-in: prefetch likely areas (respawn points, recent areas) | enable for fast-travel games |
| `EnableSLIMAvatars` | lightweight distant avatars | see SLIM |

## Per-model control: `Model.ModelStreamingMode`
| Mode | Behaviour | Use for |
|---|---|---|
| `Nonatomic` (default) | parts stream individually | most content |
| `Atomic` | all initial descendants arrive together (then `WaitForChild` on the model only) | interactables whose scripts need the whole model (doors, NPC rigs) |
| `Persistent` | sent at join (before `Workspace.PersistentLoaded`), never streams out | rare: a few parts client scripts must always read; **never whole maps** |
| `PersistentPerPlayer` | persistent for players added via `model:AddPersistentPlayer(player)`, atomic for others | player-owned base/plot |

## Controlling what streams
- `player:RequestStreamAroundAsync(position, timeout?)` (server or client) before teleporting a player inside the
  world or showing a cutscene elsewhere; server call it before `PivotTo` for smooth teleports.
- `Player.ReplicationFocus` (focus other than the character, e.g. spectator camera target) and
  `player:AddReplicationFocus(part)` / `RemoveReplicationFocus` (multiple foci cost server work — few only).
- Pause UI: `GuiService:SetGameplayPausedNotificationEnabled(false)` + react to `Player.GameplayPaused`.

## LOD and SLIM
- `Model.LevelOfDetail` (Studio/plugin-writable only): `Automatic` / `StreamingMesh` / `SLIM` / `Disabled`. With streaming, distant
  models render as imposter meshes when streamed out. SLIM = highest-fidelity automatic LOD generated by cloud
  transcoding. Requirements: streaming on, place **saved to Roblox** (not a local .rbxl) with **Team Create**
  enabled; wait 1–2 min after first publish, then rejoin. Best for static geometry — runtime changes to parts,
  materials or geometry break the SLIM representation.
- `Workspace.EnableSLIMAvatars` = SLIM for avatar characters.
- Custom LOD (your own): swap detail models by distance on the client at low frequency (0.5–2 Hz), hysteresis to
  avoid flicker; keep gameplay colliders server-side and unchanged.

## Large-world architecture
- Chunk the world logically (regions/rooms) with stable ids; server owns gameplay state per chunk; clients render
  whatever is streamed and ask for state by id.
- Keep interactive objects as tagged models (Atomic if their scripts need the whole model).
- Keep anchored static geometry anchored (anchored assemblies stream part-by-part efficiently).
- Avoid huge moving assemblies (they stream as one unit → spikes).
- Don't move the whole map into ReplicatedStorage to "avoid streaming bugs": that loads everything on every client.
- Mobile memory: prefer lower target radius, Opportunistic stream-out, fewer unique textures/meshes, fewer
  persistent models.

## Debugging
Network Summary overlay: Shift+Ctrl+F3, then Shift+1 cycles to the Streaming panel (loaded regions visualised).
Temporarily raise `Player.CameraMaxZoomDistance` to see streamed regions from above. Test with a small
`StreamingTargetRadius` to flush out scripts that assume presence.

## Streaming-safe client script checklist
- [ ] No top-level indexing of Workspace descendants without `WaitForChild`+timeout or binder.
- [ ] Bindings idempotent; cleanup on removal; re-bind on re-add.
- [ ] Remote handlers tolerate `nil` Instances.
- [ ] Local visual state re-applied on stream-in (don't store it only on the Instance).
- [ ] UI doesn't reference world parts that can vanish without checks.
