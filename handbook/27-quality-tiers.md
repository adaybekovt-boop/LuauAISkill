# 27. Графические профили и устойчивый FPS

Срез проверки: **26 сентября 2026**. Это авторская рабочая методика, не полный перевод официальной страницы. Непроверенные в Studio рецепты требуют отдельного запуска.


## Три разных цели
High — максимальная подтверждённая детализация. Medium — сохранение художественного направления при меньших затратах. Low — читаемость, управление и честность игры при строгом бюджете. Не строить low как случайное отключение половины объектов. Главный маршрут, входы, противники и предупреждения остаются понятными.

## Авторская таблица решений
Уменьшать декоративные particles, частоту distant animation, дальние мелкие props, стоимость postprocess и число необязательных теневых источников. Сохранять силуэт сцены, основные light cues, collision, серверные правила и UI accessibility. Для каждого изменяемого компонента определить fallback заранее.

Автоматический tier controller нуждается в hysteresis и cooldown: ухудшение реагирует на устойчивую перегрузку, улучшение — на запас, а не на один хороший кадр. Не переключать 60 свойств туда-обратно каждую секунду. Не пытаться принудительно переписать защищённые пользовательские настройки renderer через недоступные API.

## Матрица устройств
Нужны реальные тесты на целевых устройствах. Studio emulator полезен для layouts и части поведения, но не доказывает GPU performance телефона. В report фиксировать модель устройства, разрешение, graphics level, сборку, battery/power mode, количество игроков и продолжительность. Не экстраполировать RTX 3090 на весь Roblox.

## Приёмка
Один маршрут проходится при всех tiers; декоративный fog не превращается в обязательное укрытие; низкий tier не раскрывает противника сквозь стены; динамическое переключение не удаляет чужие объекты и не сохраняет локальный выбор как server global. Для bodycam добавить отдельный motion toggle, независимый от graphics quality.
