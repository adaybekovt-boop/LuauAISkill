# 41. MicroProfiler: от симптома к проверенной причине

Авторский синтез; проверка первичных источников 26.09.2026. Не официальный перевод и не отчёт о выполненном Studio-тесте.

## Доказательство bottleneck
Начать с воспроизводимого маршрута и фиксированных настроек. Записать устройство, build, resolution, quality, количество игроков, длительность и прогрев. Сначала увидеть frame-time spike, затем найти конкретный task на timeline. Если FPS ограничен сверху, одинаковые 60 FPS не доказывают одинаковый запас производительности.

MicroProfiler разделяет выполнение engine tasks и помогает оценивать main/worker/render работу. Цвет frame bars — диагностическая подсказка, не цель оптимизации; смотреть длительности и зависимости. Собственный счётчик PreRender измеряет интервал callbacks, не непосредственное GPU время. Не переименовывать его в GPU benchmark.

## Инструментация
Для вычислительных участков использовать сбалансированные debug.profilebegin/profileend labels с понятными именами. Не вставлять подробный лог в inner loop — он меняет нагрузку. Статистику считать в bounded buffers и с допустимой частотой агрегации. Отдельно учитывать стоимость измерения.

Выбрать гипотезу: например, десятки одинаковых spatial queries per-frame или создание новых emitter instances при каждом событии. Сначала измерить baseline, затем изменить только эту причину, повторить сценарий и убедиться в прежнем gameplay/визуальном результате. Несколько прогонов и distribution важнее одного лучшего числа.

## Современный agent workflow
Текущая документация описывает анализ paused capture через Studio Assistant и MCP. Это полезный инструмент, когда он действительно доступен. Агент должен получить реальный capture и ссылку/путь, а не строить график по предполагаемой нагрузке. Наличие такой возможности на странице не означает, что в текущем чате есть подключённый Studio инструмент.

Сохранять raw dump рядом с параметрами теста. Ограниченная запись содержит выбранные frames, не всё время сессии; не экстраполировать её на весь плейс. Client и server dumps отвечают на разные вопросы. Победа на мощном desktop не закрывает мобильное устройство с прогревом/thermal throttling. Оптимизацию, которая лишь скрыла нагрузку переносом на другой кадр или клиент, оценивать по всей системе.
